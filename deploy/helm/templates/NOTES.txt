The MCP server is reachable inside the cluster at:

  http://{{ include "zoekt-mcp-server.fullname" . }}-mcp.{{ .Release.Namespace }}.svc:{{ .Values.mcp.service.port }}

{{ if .Values.indexer.enabled -}}
The index is empty until the indexer has run. It is scheduled at {{ .Values.indexer.schedule | quote }};
to build it now rather than waiting:

  kubectl -n {{ .Release.Namespace }} create job --from=cronjob/{{ include "zoekt-mcp-server.fullname" . }}-indexer first-index
  kubectl -n {{ .Release.Namespace }} logs -f job/first-index

{{ else -}}
The indexer is disabled, so nothing populates /data/index. Enable it, or write
the index into that volume yourself.

{{ end -}}
{{- if .Values.ingress.enabled }}
Agents reach it at https://{{ .Values.ingress.host }}{{ .Values.ingress.path }}

  export ZOEKT_MCP_AUTH_TOKEN=$(kubectl -n {{ .Release.Namespace }} get secret {{ include "zoekt-mcp-server.authSecret" . }} -o jsonpath='{.data.token}' | base64 -d)
  claude mcp add --transport http zoekt-mcp https://{{ .Values.ingress.host }}{{ .Values.ingress.path }} \
    --header "Authorization: Bearer $ZOEKT_MCP_AUTH_TOKEN"
{{- else }}
No Ingress is enabled, so nothing outside the cluster can reach it yet. To try
it from your machine:

  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "zoekt-mcp-server.fullname" . }}-mcp {{ .Values.mcp.service.port }}:{{ .Values.mcp.service.port }}

The token is required over the forwarded port too; without it every request is
answered with 401.

  export ZOEKT_MCP_AUTH_TOKEN=$(kubectl -n {{ .Release.Namespace }} get secret {{ include "zoekt-mcp-server.authSecret" . }} -o jsonpath='{.data.token}' | base64 -d)
  claude mcp add --transport http zoekt-mcp http://127.0.0.1:{{ .Values.mcp.service.port }}/ \
    --header "Authorization: Bearer $ZOEKT_MCP_AUTH_TOKEN"
{{- end }}

Zoekt itself is deliberately a ClusterIP with no Ingress. It has no
authentication of its own, so anything that can reach it can read every
repository you indexed. Keep it that way.
